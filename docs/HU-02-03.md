# HU-02-03 — Guardado de cambios en el perfil académico

## 1. Historia de usuario

> **Como** estudiante
> **Quiero** guardar los cambios realizados en mi perfil académico
> **Para** que la información quede almacenada y disponible para consultas o simulaciones futuras.

## 2. Criterios de aceptación

1. Confirmación visual de guardado exitoso.
2. Manejo de errores si el guardado falla.
3. No se debe perder información ya cargada si ocurre un error.

## 3. Estado actual (2026-09-08)

El guardado del perfil ocurre en [`StudentDashboard.tsx`](../frontend/src/pages/StudentDashboard.tsx) (ruta `/estudiante`), dentro de `handleGuardar()` (líneas 40-64). Al enviar el formulario se llama a `actualizarPerfil()` ([`estudianteApi.ts`](../frontend/src/api/estudianteApi.ts)), que hace `PATCH /estudiante/perfil`, atendido por `EstudianteService.actualizarPerfil()` ([`estudiante.service.ts:94-116`](../backend/src/estudiante/estudiante.service.ts#L94-L116)), el cual persiste los campos recibidos con `prisma.user.update()`.

| Criterio | Estado | Detalle |
|---|---|---|
| 1. Confirmación visual de guardado exitoso | ✅ | Si `actualizarPerfil()` no lanza error, se vuelve a pedir el perfil (`getPerfil()`), se actualiza el estado local, se cierra el modo edición (`setEditando(false)`) y se fija `mensajeGuardado = 'Perfil actualizado correctamente.'`, que se renderiza como `<p className="page-success">` en la vista de solo lectura. El mensaje persiste hasta que el estudiante vuelve a entrar en modo edición (`iniciarEdicion()` lo limpia) o navega y vuelve a montar el componente. |
| 2. Manejo de errores si el guardado falla | ✅ | El `catch` de `handleGuardar()` distingue por código HTTP: `409` (código estudiantil duplicado) muestra el mensaje del backend o uno genérico de conflicto; `400` (validación del DTO) muestra el/los mensajes de validación; cualquier otro caso muestra `'No se pudo guardar tu perfil.'`. El mensaje se pinta como `<p className="page-error">` dentro del propio formulario, y el botón "Guardar cambios" queda deshabilitado mientras `guardando` es `true` (evita reenvíos duplicados) y vuelve a habilitarse en el `finally`. |
| 3. No perder información ya cargada si ocurre un error | ✅ | Ante un error, el `catch` solo asigna `errorGuardado`; no se toca `nombreCompleto` ni `codigoEstudiantil` (los valores que el estudiante escribió permanecen en los inputs) ni el `perfil` ya cargado en pantalla. El formulario tampoco se cierra (`editando` sigue en `true`), por lo que el estudiante puede corregir el dato señalado y reintentar sin volver a escribir todo. |

## 4. Detalles de la implementación

- **Persistencia real**: `EstudianteService.actualizarPerfil()` actualiza directamente la fila del usuario en la base de datos (`NombreCompleto`, `codigoInstitucional`), por lo que los cambios quedan disponibles de inmediato para cualquier consulta posterior del perfil (`obtenerPerfil()`) y para las pantallas que dependen de esos campos.
- **Validación de duplicados**: antes de guardar, el backend verifica que el nuevo `codigoEstudiantil` no esté en uso por otro usuario (`findFirst` excluyendo el propio `userId`); si está en uso, lanza `ConflictException` (409), que el frontend traduce al mensaje de error correspondiente.
- **Doble lectura tras guardar**: el frontend no asume que la respuesta del `PATCH` refleja el estado final; vuelve a pedir el perfil completo con `getPerfil()` antes de mostrar la confirmación, garantizando que lo mostrado en pantalla coincide con lo almacenado.
- **Estado de carga**: `guardando` controla tanto el `disabled` de los botones "Cancelar"/"Guardar cambios" como la clase `btn-loading`, dando además una señal visual de que la operación está en curso.

## 5. Gap identificado

Ninguno respecto a los tres criterios de aceptación: los tres se cumplen con el código actual. Como observación menor, el mensaje de éxito (`mensajeGuardado`) no tiene expiración automática ni botón de cierre; permanece visible indefinidamente hasta la próxima edición o navegación, lo cual no viola el criterio pero podría revisarse como mejora de UX si se considera relevante.
